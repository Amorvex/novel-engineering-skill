# 小说工程 skill：四场景前向走查

本报告为静态流程验证：已阅读 `SKILL.md`、七份适用参考（含可选工作记录模板）。以下仅推演在虚构条件下应采取的行动与状态；未实际审读小说、修改小说、查询 agent 状态或执行正文提交。引用路径均相对 skill 目录。

## 1. 安静现实主义短篇中的单处笔误

依据：主文“简单查询或单处笔误直接处理”、质量边界；`references/tools.md` 文件模式。

1. 读取已有说明和必要的局部正文，确认作者“不反转”的决定与目标位置；无需加载全书、创建数据库、目标卡或多 agent 流程。
2. 确认笔误及输入内容版本，只准备该处候选修改。作者没有要求结构审查，不据安静、留白或无反转提出改造。
3. 在确有相应文件能力且单写者条件成立时，保存前重读核对基线、保留旧版本、使用同目录临时文件及原子替换，最后回读确认只有预期变化。
4. 仅更新已有记录中实际受影响的项目；若不影响事实与摘要，不制造人物状态、伏笔或全篇审查任务。

预期状态：保存及回读成功才可记“已提交”；局部笔误核对完成。文学审查、小弧阅读和独立审查记“本任务不适用：仅单处笔误”，不能声称整篇已验收。没有 subagent 本身不妨碍完成笔误任务。

歧义/限制：主文核心循环未显式标明哪些步骤可被笔误分支跳过，但参考选择已有明确豁免，宜按最小任务解释。更实质的问题是“只有普通文件读写”未必提供原子替换或锁：不能由读写能力推定具有这些能力。若无法确认单写者或无法安全替换，应保留候选修改并将正式保存标为未完成，报告具体能力缺口；不能虚称完成文件适配流程。skill 可补充低能力环境的明确降级策略。

## 2. 接手第 7 章：声称提交、未回读且版本不符

依据：`references/continuation.md`、`references/tools.md`、`references/collaboration.md`。

1. 先定位唯一当前状态源、接续入口、任务 ID、输入版本、候选产物、历史保存证据和前任提交者标识。前任口述不构成已提交证据。
2. 将提交状态记为“提交结果待核”，版本差异及旧 agent 状态未知分别记录。暂不重新派写、不复写第 7 章、不将旧意见套用到当前版本。
3. 若可访问运行状态接口则查询；不可访问则保持“运行状态未知”，不假设能控制旧 agent。核对谁可能写正式正文，建立唯一正式提交者；无法排除并行正式写入时停止正式写入，读证据与准备候选仍可继续。
4. 读取当前章、旧基线、候选稿和可用历史，判断差异来源。当前文件与输入基线不一致本身既不能证明提交成功，也不能证明失败。
5. 若当前稿及历史能证明前次产物已经保存，补回读、核对结果并同步受影响记录；若证明未保存且基线仍相符，才可续提。当前场景既有版本不符，不能直接进入“续提”。若仍无法判断，保持待核并写明下一项待取证事实。
6. 迟到产物仅作为带版本的候选保存，不覆盖新稿。依赖版本发生变化的记忆、审查结论标“待复核”，按实际影响恢复最小未完成单元。

可能终态：证据充分时“已提交待同步”，同步完成后再关闭；证据不足时继续“提交结果待核”。“已验收”“已提交”和“已关闭”不得互相替代。

歧义/限制：skill 正确说明检查点不是锁，但没有定义跨聊天的提交者交接标记、租约或如何证明旧写者已停止。在旧主 agent 或其他进程可能继续正式写入且无锁时，只能暂停正式提交，不能靠新任务记录实现互斥。旧子 agent 若严格仅写指定产物目录，其状态未知不应自动阻塞所有只读恢复工作。

## 3. 已出场城市的图片，含未定飞行器

依据：`references/materials.md`、主文事实分类与作者决定边界。

1. 保留图片原件与作者原话，为其建立稳定 ID 及相对路径。实际查看图片；若无法查看，明确“未查看”，不推断画面。
2. 场景存在状态记“已出现”，证据可先注明“作者确认”；定位到正文后补章号、位置与版本。作者已明确不重写首次出场，无需再次询问。
3. 素材定位记“视觉参考”，并明确不安排新首次出场、不自动返修原段落。完成整理但尚无调用场景，可记“暂存：供后续相关场景参考”，细节采用状态仍为“未核对”。
4. 将城市可见外观与画中飞行器分别记录。飞行器仅是图片可见元素，不直接写为世界既有交通工具、能力、历史或物理规则；标作候选细节，尚未确认是否采用。未定不等于与正文冲突，不应无证据标“待解决冲突”。
5. 若后续写作确需采用会改变世界规则的飞行器，先提出具体采用范围供作者决定；当前只是入库，可直接暂存该细节，不阻塞整理。未来正式稿采用并保存回读后，才登记具体位置与版本。

预期状态：城市“已出现”；图片“暂存”或按实际计划“待安排”；飞行器“候选、未采用”；正文无修改。本场景不产生“已采用”状态。

歧义：素材处理状态没有“已整理仅参考”，用“暂存”虽可表达，但需要理由避免被误读为搁置作者要求。还应区分“图片作为参考必须保留”和“画面每项细节必须入文”；现有规则倾向正确，但可明确这一区别。

## 4. 完整悬疑小弧的独立阅读，目标卡包含结局

依据：`references/arc-reading.md`、`references/project.md` 悬疑重点、`references/collaboration.md`。

1. 主 agent 确认小弧正文范围与版本，选择未参与该段写作且具独立上下文的审查者。提供正文定位、版本、阅读顺序和最少前情；前情只能含读者在小弧开始时已知的事实。
2. 第一阶段按作品呈现顺序读取正文，每次一个可管理单元，包括结局在正文中正常出现的位置。不能先看结局摘要、目标卡、规划、后续章摘要、写作者辩护或提前泄底的既有审查意见。
3. 每单元保存即时投入、疑问、预期及情绪反应；不知道未来答案时的反应要保留，不能在看完结局后覆写成事后判断。先落盘完整原始阅读轨迹，再进入第二阶段。
4. 第二阶段才提供含结局的目标卡、作者决定及适用约束，对照线索公平性、知情顺序、回应与余味等，区分有意保留的疑问和实际因果缺口。若目标卡为事后整理，明确标注。
5. 报告包含版本、位置、证据、阅读影响、判断性质和可选修改。主 agent 裁决后再安排必要返修及复核，不以一个审查者的感受冒称普遍读者结论。

状态顺序：“未开始”→“第一阶段进行中”→“原始轨迹已保存”→“第二阶段对照中”→按结果“待返修”或“已验收”。独立阅读、连续性与机械扫描分别记状态。没有真正独立执行者时只能标“自查；待独立审查”，不能靠换提示词声称独立。

关键歧义：通用任务包要求包含“目标”，但第一阶段明确禁止提供目标卡，应以分阶段专项规则优先，只提供阅读任务目标，不提供故事预期答案。主 agent 已知结局并不污染隔离良好的审查者；但若审查者继承完整聊天、读取合并式计划文件或接触含结局的任务包，独立初读就已受污染，无法通过要求“忘掉”补救。现有 skill 未明确禁止继承上下文，建议补上“使用不含目标卡及未来答案的新上下文；若已污染，换独立执行者或标明限制”。

## 总体判断

四场景均有可用的主路径，尤其能避免强加反转、重试不明提交、图片自动变设定和初读提前暴露目标卡。需要补强的主要是：低能力文件环境的安全保存降级、旧提交者交接的可验证条件，以及独立阅读上下文的防剧透隔离。以上为流程静态验证结论，不代表任何小说或实际提交已通过验收。
